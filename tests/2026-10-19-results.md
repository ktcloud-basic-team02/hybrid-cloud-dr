## 반영한 변경

`app/db.py`에 `connect_timeout=3`, `read_timeout=5`, `write_timeout=5`를 추가했습니다. PR #8로 main에 머지했으며 image-scan 검사를 통과했습니다. 이 값들은 각 단계의 제한이며 HTTP 요청 전체 제한이 아닙니다.

## 검증 범위

- 파드 삭제는 정상 종료 방식이며 갑작스러운 노드/AZ 장애를 재현하지 않았습니다. 요청 실패 0건은 이번 부하와 조건에서의 관측 결과입니다.
- DB pause는 프로세스를 정지한 상황입니다. `/health` 로그에서 연결 초기 서버 응답을 기다리는 현상도 확인됐으므로, 실행 중 쿼리의 응답 지연만을 분리한 테스트는 아닙니다. 연결·쓰기 제한 자체는 별도로 검증하지 않았습니다.
- DB 무응답 중 주문 시도는 DB가 이미 정지된 상태에서 시작했습니다. 재고 차감 후 장애, 트랜잭션 중간 롤백, commit 결과 불명확 상황은 검증하지 않았습니다.
- S3의 0.126초는 DB 복원 구간만의 시간입니다. 다운로드·확인·접속 전환 시간을 포함한 전체 RTO는 측정하지 않았으며, 복제본 실행 전 상태 기록은 확보하지 못했습니다.
- 동일 요청 재전송 결과는 일반 브라우저의 이중 클릭 재현 결과가 아닙니다. 해당 테스트 계정·주문과 로컬 임시 쿠키 파일의 정리는 이 기록 작성 시 완료 확인을 받지 못했습니다.
